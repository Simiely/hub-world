# 开发 README — 关键问题与修正记录

记录本项目在**文档核查**与 **HTML 交付**过程中遇到的关键技术坑与正确做法。日后遇到同类 3D / 渲染 / 减面 / 文档标注问题，可直接按条目检索参考。

---

## 1. 自动减面算法归属

- **坑**：把 `Simplygon / ProOptimizer / ZBrush Decimation Master` 并列说成「都采用二次误差度量（QEM）」。
- **正**：QEM（Garland & Heckbert 1997）是 Simplygon / ProOptimizer 的基础算法族；Decimation Master 是 Maxon **专有算法**，底层机制未公开，不能武断归为 QEM。
- **影响**：不影响「自动减面不行」的论点，但属于可被证伪的具体技术断言，被懂内部机制者挑刺。
- **来源**：`[1]` SIGGRAPH'97 QEM 论文；`[6]` Maxon ZBrush 文档。

## 2. Shrinkwrap / 收缩包裹机制

- **坑**：说成「**垂直投影**」（易误解为沿世界坐标轴整齐投下）。
- **正**：它是「**吸附到高模表面最近点**」（Nearest Surface Point）或沿法线投影，各顶点朝**自己最近的曲面点**贴合，方向随高模曲率走，并非垂直。
- **来源**：`[4]` Blender Shrinkwrap 修改器手册。

## 3. Catmull-Clark 细分机制

- **坑**：简化为「在四边形四条边中点插入新顶点再连接」。Wikipedia 明确判定为**错误简化**。
- **正**：每次细分生成**三类点**——
  - **Face point（面心点）**：取该面所有顶点平均；
  - **Edge point（边点）**：取相邻面心点 + 两端顶点的**加权平均**（非纯几何中点）；
  - **Vertex point（顶点更新点）**：每个原顶点按邻域**加权重定位**。
  再重新连接成更密的纯四边形网格。所有新顶点位置都由周围旧顶点插值得到。
- **四边形前提**：10 万面低模须以 **Quad 布线**，否则 CC 细分不匀、UV 继承异常、高光仍碎。
- **来源**：`[2]` Wikipedia Catmull-Clark。

## 4. 法线烘焙的 UV 需求

- **坑**：说成「把高模细节**烘焙到 30 万面模型上**」。
- **正**：**只有低模需要 UV，高模不需要**；软件以低模 UV 为画布，从低模表面发射射线采样高模法线编码为像素。应表述为「烘焙到 **10 万面低模**生成法线贴图，30 万因继承同一套 UV 直接复用」。
- **来源**：`[3]` Wikipedia Normal mapping；`[5]` Polycount 社区共识；`[8]` Adobe Substance 3D 烘焙文档。

## 5. 「近景镜面车不能纯自动减面」的限定范围

- **坑**：泛指「车模都没法自动减面 / 没法自动减面」。
- **正**：仅在「**近景查看的镜面烤漆车**」语境下成立；远景背景车、哑光/内衬件等非镜面近景场景，仍可自动减面 + 轻修。纯自动减面产出的破碎三角面，在烤漆高光下暴露所有拼接痕迹——**漫反射可藏拙，镜面不行**。
- **来源**：`[10]` 渲染原理（镜面/高光对网格规整度极度敏感）。

## 6. 面数预算逻辑（别算错账）

- **坑**：以为「外壳 8~9 万 ×4（细分倍率）≈ 34 万 > 30 万预算」，判定超了。
- **正**：策略里外壳细分**本就奔 30 万去**（倍率随目标走，非死卡 ×4）；内饰从头到尾**不细分**、保持 1~2 万。账面是「外壳刻意细分到 30 万 + 内饰恒定低密度」，**不溢出**。
- **来源**：`[10]`。

## 7. 弱包裹（可选）的正确理解

- **坑**：说成「第二次弱包裹，迭代 1，做最后微修」——读者易误以为是在 30 万密网上改点。
- **正**：若需弱包裹，**只需回到 10 万面母版微调少量控制点**，包裹更准、要修的点**远少于直接处理 30 万密网**。这正体现了「控制点数量级差几十倍」的核心优势。
- **来源**：`[4]`。

## 8. 论文式 `[n]` 标注的关联审计

- **坑**：给技术断言**挂错**来源编号，例如：
  - 把「时间节省 50~55%」挂到 `[10]`（[10] 是镜面敏感原理，与时间估算无关）；
  - 把「手工删线疏密不均」挂到 `[9]`（[9] 是 QEM 边坍缩讲义，此句是手工删线经验）；
  - 把 `[2]` 挂到「卡死硬边」（该句无关细分算法）。
- **正**：每个 `[n]` 必须与其**旁文字**和**参考文献实际内容**严格对应。本轮审计 18 处标注，修正 4 处错位。
- **经验**：标注前先确认该论断**真正由哪条来源支撑**，不要在「同类话题」上随手挂；验证来源尽量用真实抓取/检索过的 URL，归纳性结论如实标注为「原理归纳」而非编造网页。

## 9. 部署与工程注意

- **GitHub Pages**：根目录 `index.html` 即首页入口；仓库创建用 GitHub API + `curl --data-binary @file.json` 传参（见下），避免中文描述在 shell 单引号下触发 `Problems parsing JSON`。
- **Token 安全**：
  - 不要把 token 写进 `git` 历史或 remote（`git remote -v` 会暴露）；
  - 推送用 `git remote set-url origin https://x-access-token:<token>@github.com/...`，推完立即用 `git remote set-url origin https://github.com/...` 去掉 token；
  - 临时 token 文件用完即删。
- **同文件多 Edit**：对同一个文件并发多次 Edit 会触发「文件已被修改」保护，须**串行逐个**编辑。
