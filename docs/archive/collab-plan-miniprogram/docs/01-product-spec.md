# 01 · 产品功能规格

> 上级导航：[README 总导航](./README.md)
> 本文定义**做什么**。技术怎么实现见 [02-architecture.md](./02-architecture.md)。

---

## 一、核心概念

| 概念 | 说明 |
|---|---|
| **账号 (User)** | 内置账号，用户名 + 密码登录。不是微信授权登录 |
| **计划 (Plan)** | 一条待办任务。有标题、描述、可见成员、提醒时间、完成状态 |
| **创建者 (Creator)** | 创建这条计划的账号 |
| **协作者 (Assignee)** | 创建时指定的、可见并可完成这条计划的账号，可多个 |
| **可见集合 (Members)** | `创建者 + 所有协作者`，决定谁能看到这条计划 |

## 二、功能清单

### 2.1 账号模块

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| A-1 | 账号密码登录 | 输入用户名+密码，服务端校验后签发 Token | P0 |
| A-2 | 登录态保持 | Token 存本地，有效期内免登录；过期自动跳登录页 | P0 |
| A-3 | 退出登录 | 清除 Token、本地数据、解绑当前 openid | P0 |
| A-4 | 账号↔微信绑定 | 登录成功时自动把当前 openid 绑到该账号，用于推送 | P0 |
| A-5 | 修改密码 | 需校验旧密码 | P1 |
| A-6 | 账号预置/管理 | 由管理员在云数据库直接录入初始账号 | P0 |

> ⚠️ 无「注册」功能。账号由管理员预置，符合「指定账号」的需求定位。
> 如后续要开放注册，需评估微信审核对 UGC 账号体系的合规要求，见 [11-testing-release.md](./11-testing-release.md)。

### 2.2 计划模块

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| P-1 | 创建计划 | 填标题、描述（选填）、选协作者、设提醒时间（选填） | P0 |
| P-2 | 选择协作者 | 从账号列表中多选。列表只展示账号昵称，不暴露密码等敏感信息 | P0 |
| P-3 | 待完成列表 | 展示所有「我可见 且 未完成」的计划，按提醒时间/创建时间排序 | P0 |
| P-4 | 已完成列表 | 展示所有「我可见 且 已完成」的计划，按完成时间倒序 | P0 |
| P-5 | 计划详情 | 查看完整信息：成员、提醒、完成人、完成时间 | P0 |
| P-6 | 完成计划 | 创建者或任一协作者点击即可完成，**只需一人** | P0 |
| P-7 | 撤销完成 | 把已完成的计划改回待完成（仅创建者可操作） | P1 |
| P-8 | 编辑计划 | 修改标题/描述/协作者/提醒时间（仅创建者可操作） | P1 |
| P-9 | 删除计划 | 软删除，仅创建者可操作 | P1 |

### 2.3 提醒模块

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| R-1 | 设置提醒时间 | 创建/编辑计划时选择一个未来时间点 | P0 |
| R-2 | 订阅授权引导 | 用户点击「开启提醒」时弹出微信订阅授权 | P0 |
| R-3 | 定时推送 | 到点后向所有可见成员推送订阅消息 | P0 |
| R-4 | 额度管理 | 记录每个账号的剩余推送额度，不足时提示续订 | P0 |
| R-5 | 应内提醒兜底 | 打开小程序时，对已到期未完成的计划显示红点/置顶 | P1 |

### 2.4 同步模块

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| S-1 | 启动增量同步 | 每次冷启动/热启动（超过阈值）拉取服务器差异数据 | P0 |
| S-2 | 本地持久化 | 计划数据全量存本地，断网可查看 | P0 |
| S-3 | 首屏本地优先 | 先渲染本地数据，同步完成后静默刷新，不阻塞首屏 | P0 |
| S-4 | 离线操作队列 | 断网时的创建/完成操作入队，联网后自动重放 | P1 |
| S-5 | 手动下拉同步 | 列表页下拉触发一次强制同步 | P0 |

## 三、任务状态机

```
                    ┌──────────────┐
     创建计划  ───►  │   pending    │  待完成
                    │  （未完成）   │
                    └──────┬───────┘
                           │
        创建者 或 任一协作者 点击「完成」（只需一人）
                           │
                           ▼
                    ┌──────────────┐
                    │     done     │  已完成
                    │  （已完成）   │  记录 completedBy / completedAt
                    └──────┬───────┘
                           │
              仅创建者可「撤销完成」（P1）
                           │
                           ▼
                       回到 pending

  任意状态 ──仅创建者「删除」──► deleted:true（软删除，列表不可见）
```

**状态字段**

| 字段 | 取值 | 说明 |
|---|---|---|
| `status` | `pending` \| `done` | 业务完成状态 |
| `deleted` | `false` \| `true` | 软删除标记，**不可硬删除**（同步依赖） |
| `completedBy` | `userId` \| `null` | 谁完成的 |
| `completedAt` | 时间戳 \| `null` | 何时完成 |

## 四、权限矩阵

> 所有权限校验**必须在云函数内做**，前端隐藏按钮只是体验优化，不构成安全边界。

| 操作 | 创建者 | 协作者 | 无关账号 |
|---|:---:|:---:|:---:|
| 查看计划 | ✅ | ✅ | ❌ |
| 完成计划 | ✅ | ✅ | ❌ |
| 撤销完成 | ✅ | ❌ | ❌ |
| 编辑计划 | ✅ | ❌ | ❌ |
| 删除计划 | ✅ | ❌ | ❌ |
| 接收提醒 | ✅ | ✅ | ❌ |

**判定逻辑（云函数伪代码）**

```js
const canView    = plan.memberIds.includes(userId);   // memberIds = [creatorId, ...assigneeIds]
const canComplete = plan.memberIds.includes(userId);
const canManage   = plan.creatorId === userId;
```

## 五、页面结构与导航

```
┌─────────────────────────────────────────────────┐
│  login  账号密码登录页（非 tab，无登录态时跳转）    │
└──────────────────────┬──────────────────────────┘
                       │ 登录成功
                       ▼
┌─────────────────────────────────────────────────┐
│                   TabBar（主包）                 │
├──────────────┬──────────────┬───────────────────┤
│  ① 待完成     │  ② 已完成     │  ③ 我的           │
│  pages/todo  │  pages/done  │  pages/profile   │
└──────┬───────┴──────┬───────┴────────┬──────────┘
       │              │                │
       └──────┬───────┘                │
              ▼                        ▼
    pages/plan-detail            设置 / 修改密码
      计划详情（主包）              / 提醒额度（主包）
              │
              │ 创建 / 编辑
              ▼
  ┌───────────────────────────────────┐
  │      packageA（分包，按需加载）      │
  ├───────────────────────────────────┤
  │  plan-edit    创建/编辑计划页       │
  │  member-pick  选择协作者页          │
  └───────────────────────────────────┘
```

**分包理由**：创建/编辑页依赖日期选择器、多选组件等较重 UI，属于低频操作，放分包可显著减小主包体积。详见 [02-architecture.md](./02-architecture.md) 的包体积规划。

## 六、关键交互规则

### 6.1 「至少一人完成」的并发处理

两个成员**同时**点击完成时：

- 第一个请求成功 → 状态变 `done`，记录该用户为 `completedBy`
- 第二个请求 → 云函数条件更新命中 0 条 → 返回友好提示「该计划已由 XXX 完成」，**不报错**
- 前端两边都刷新为已完成状态

> 实现要点：用带 `status: 'pending'` 条件的原子更新，不要「先查后写」。详见 [04-sync-design.md](./04-sync-design.md) 冲突解决章节。

### 6.2 首屏加载策略（不能白屏等网络）

```
onLoad
  ├─ 1. 同步读本地缓存 → 立即 setData 渲染列表（0ms 出内容）
  ├─ 2. 后台并发调用 sync 云函数
  └─ 3. 同步返回后，若有差异 → 静默局部更新列表 + 顶部轻提示「已更新 N 条」
```

### 6.3 订阅授权的时机

| ✅ 正确时机 | ❌ 错误时机 |
|---|---|
| 用户在创建页点击「开启提醒」开关 | 页面 `onLoad` 自动弹 |
| 用户在「我的」页点击「续订提醒额度」 | 登录成功后自动弹 |
| 完成计划后弹卡片引导（转化率高） | 定时器延迟弹 |

> 微信强制要求 `requestSubscribeMessage` 必须由**用户点击手势**触发，非手势调用直接失败。

## 七、非功能性要求

| 指标 | 目标值 |
|---|---|
| 冷启动到首屏可交互 | < 1.5s（中端安卓） |
| 主包体积 | < 1.5MB |
| 列表页本地渲染 | < 100ms（走缓存，不等网络） |
| 单次增量同步耗时 | < 800ms（日常增量 < 50 条） |
| 断网可用性 | 可查看全部已缓存计划；完成操作入队 |
| 提醒送达时间误差 | ≤ 1 分钟（受定时触发器最小粒度限制） |

---

## 八、明确不做的（范围边界）

避免需求膨胀，以下明确**不在当前版本范围**：

- ❌ 微信授权登录 / 手机号登录（已选定内置账号体系）
- ❌ 自助注册、找回密码（账号由管理员预置）
- ❌ 计划评论、附件上传、图片
- ❌ 重复提醒（每天/每周循环）—— 仅支持单次提醒
- ❌ 子任务、任务分组、标签
- ❌ 多人「都必须完成」模式 —— 需求明确是「至少一人」
- ❌ 消息中心、站内信
