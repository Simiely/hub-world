## 一、测试矩阵

### 1.1 设备与系统

| 维度 | 必测 | 说明 |
|---|---|---|
| iOS | iPhone（较新 + 较旧各一台） | ⚠️ iOS 日期解析严格，`new Date('2026-07-31 19:03')` 会返回 Invalid Date |
| Android | 中端机（如红米、荣耀） | ⭐ 性能基准以中端安卓为准，不看旗舰 |
| 微信版本 | 最新版 + 落后 2 个版本 | 基础库兼容性 |
| 屏幕 | 小屏（SE）+ 大屏 + 全面屏 | 安全区适配 |

> 🔴 **不要只在开发者工具测**。工具与真机差异见 [09-pitfalls.md P31](./09-pitfalls.md)。

### 1.2 网络条件

- [ ] 正常 WiFi
- [ ] 4G
- [ ] 弱网（开发者工具「网络」模拟 2G / 慢速 3G）
- [ ] 飞行模式（完全离线）
- [ ] 离线 → 联网切换（验证队列重放）
- [ ] 请求超时（模拟服务端慢响应）

## 三、安全检查

- [ ] 所有集合权限为「仅管理端可读写」
- [ ] 前端 console 执行 `wx.cloud.database().collection('users').get()` → 报权限错误
- [ ] 前端 console 执行 `wx.cloud.database().collection('plans').get()` → 报权限错误
- [ ] 全局搜索 `event.userId` → 0 个结果
- [ ] `AUTH_SECRET` 在环境变量，未提交仓库
- [ ] 成员列表接口用 `field` 白名单，不含 username/passwordHash
- [ ] 云函数返回体无敏感字段
- [ ] 日志无密码、无完整 Token
- [ ] 抓包尝试篡改 planId 操作他人计划 → 被拒绝

## 五、提审准备

### 5.1 小程序后台配置

- [ ] 基本信息：名称、图标、简介、服务类目
- [ ] 🔴 **用户隐私保护指引**（「设置」→「服务内容声明」）
  - 声明收集：账号信息、设备信息（用于消息推送）
  - 说明用途：身份识别、协作展示、提醒推送
- [ ] 订阅消息模板已通过审核
- [ ] 云开发环境为**正式环境**（不是开发环境 ID）
- [ ] 版本号与描述填写

### 5.2 🔴 提审备注模板（最容易被忽略）

```
【测试账号】
账号1：test001   密码：Test123456
账号2：test002   密码：Test123456

【功能说明】
本小程序为组织内部协作计划管理工具。
账号由管理员统一分配，不开放公开注册，因此登录页无注册入口。

【完整体验路径】
1. 用 test001 登录
2. 首页「待完成」可见预置的示例计划
3. 点右下角「+」创建计划，可勾选 test002 作为协作者
4. 点计划卡片右侧按钮完成任务，任务移入「已完成」
5. 创建计划时可设置提醒时间，到点通过订阅消息推送

【订阅消息说明】
用于向计划成员发送到期提醒，用户主动点击「开启提醒」后授权，
单次授权对应单次推送，符合订阅消息使用规范。

【已预置测试数据】
test001 账号下已有 3 条待完成、2 条已完成的示例计划。
```

> 🔴 **不写测试账号 = 必被驳回**。审核员打开就是登录页，进不去。见 [09-pitfalls.md P37](./09-pitfalls.md)。

### 5.3 提审前最后确认

- [ ] 测试账号真的能登录（自己再试一遍）
- [ ] 测试账号下有预置数据（不是空白页）
- [ ] 所有页面无死链、无空白页
- [ ] 无「敬请期待」「开发中」等占位内容
- [ ] 无外部支付引导、无诱导分享
- [ ] 无未备案的外部链接
- [ ] `miniprogramState` 已切换为 `formal`（发布后）
- [ ] 云函数已全部部署到**正式环境**
- [ ] 已上传体验版并内部试用过

## 六、常见驳回原因速查

| 驳回理由 | 原因 | 解法 |
|---|---|---|
| 无法完整体验 | 没提供测试账号 | 备注里写清账号密码 |
| 未配置隐私指引 | 后台未声明 | 配置用户隐私保护指引 |
| 类目与内容不符 | 选错服务类目 | 选「工具 - 效率」类 |
| 诱导分享 | 分享才能用某功能 | 移除强制分享 |
| 内容为空 | 页面无实际内容 | 预置示例数据 |
| 订阅消息用途不符 | 模板与实际场景不匹配 | 选对模板，备注说明用途 |
| 存在未上线功能 | 有"开发中"占位 | 隐藏未完成功能 |

## 七、发布后监控

上线后一周内每天检查：

| 监控项 | 位置 | 异常阈值 |
|---|---|---|
| 云函数错误率 | 云开发控制台 → 云函数 → 监控 | > 1% |
| 云函数调用量 | 同上 | 突增 3 倍以上 |
| 数据库读写次数 | 云开发 → 数据库 → 监控 | 接近配额 |
| 推送成功率 | 查 `push_logs` 集合统计 | < 90% |
| 小程序崩溃率 | 小程序后台 → 运维中心 | > 0.1% |
| 用户反馈 | 小程序后台 → 意见反馈 | 有即处理 |

**应急预案**
- 云函数出严重 bug → 回滚到上一版本（云开发支持版本管理）
- 数据同步出错 → 引导用户用调试面板「强制全量重同步」
- Token 泄露 → 更换 `AUTH_SECRET` 环境变量，强制全员重登
